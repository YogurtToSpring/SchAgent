# CampusFlow 平台化架构说明

当前前端已经从“单页聊天助手”升级为“模拟校园信息平台 + 内嵌智能体助手”。

## 1. 新定位

系统不再只是一个聊天页面，而是一个模拟学校系统平台：

```text
登录
  ↓
角色权限
  ↓
校园平台主页
  ├─ 首页概览
  ├─ 班级管理（教师）
  ├─ 班级课表 / 我的课表
  └─ 智能助手
```

这个定位的好处是：助手不是孤立回答，而是基于平台里的用户、班级、课表、天气等业务数据完成任务。

## 2. 角色设计

当前版本有两类用户：

| 角色 | 示例账号 | 权限 |
|---|---|---|
| 教师管理员 | teacher / 123456 | 管理班级、调整学生班级、维护班级课表、使用教师视角助手 |
| 普通学生 | student / 123456 | 查看本人课表、使用学生视角助手 |

后续可以扩展：

```text
super_admin
平台超级管理员

teacher
教师 / 辅导员

student
学生
```

## 3. 前端模块

```text
src/App.vue
平台总控：登录状态、当前页面、平台 Mock 数据。

src/pages/LoginPage.vue
登录页：区分教师管理员和普通学生。

src/components/PlatformLayout.vue
平台布局：左侧导航、顶部用户信息、退出登录。

src/pages/DashboardPage.vue
首页概览：展示班级数、学生数、课程数、天气。

src/pages/ClassAdminPage.vue
教师管理页：创建班级、调整学生班级、添加课程。

src/pages/SchedulePage.vue
课表页：教师看班级课表，学生看本人课表。

src/pages/ChatPage.vue
智能助手页：复用原聊天界面，但现在会携带当前登录用户和平台上下文。

src/data/platformData.js
平台 Mock 数据：用户、班级、学生、课程、天气。
```

## 4. 数据流

### 登录数据流

```text
LoginPage 输入账号密码
  ↓ emit('login', user)
App.vue 保存 currentUser
  ↓
PlatformLayout 按角色生成导航
```

### 班级管理数据流

```text
ClassAdminPage 表单操作
  ↓ emit('add-class' / 'assign-student' / 'add-course')
App.vue 修改 classes / students / courses
  ↓
DashboardPage、SchedulePage、ChatPage 自动接收最新数据
```

### 智能助手数据流

```text
ChatPage 用户提问
  ↓
sendMessage({
  session_id,
  message,
  user_context,
  platform_context
})
  ↓
后端或 Mock 智能体
  ↓
返回 answer、steps、tool_calls、artifacts
  ↓
前端显示回答和工具轨迹
```

## 5. 助手为什么更像真实场景

原来的助手只能回答：

```text
明天有没有课？
```

现在助手知道：

```text
当前用户是谁
当前用户是老师还是学生
学生属于哪个班
老师管理哪些班
平台里有哪些班级
平台里有哪些课程
当前天气是什么
```

所以它能回答：

```text
教师：检查软件工程1班周三有没有课表冲突
学生：明天上课如果下雨适合骑车吗
```

这比普通聊天机器人更有场景化优势。

## 6. 可扩展模块设计

后续模块不要直接塞进助手，而是先作为平台业务模块，再给助手增加工具。

示例：

| 模块 | 平台页面 | 智能体工具 |
|---|---|---|
| 成绩系统 | 成绩查询、成绩分析 | `grade_query_tool`, `grade_analysis_tool` |
| 论坛系统 | 帖子列表、发帖、搜索 | `forum_search_tool`, `post_create_tool` |
| 会议模块 | 会议列表、预约会议 | `meeting_query_tool`, `meeting_create_tool` |
| 通知模块 | 通知发布、提醒管理 | `notification_send_tool`, `todo_create_tool` |

扩展原则：

```text
新增业务模块
  ↓
新增后端 API
  ↓
新增智能体工具
  ↓
前端新增页面或 artifact 渲染类型
```

## 7. 第一版边界

第一版建议只做到：

```text
1. 登录与角色区分
2. 教师班级管理
3. 教师课表维护
4. 学生课表展示
5. 天气数据展示
6. 智能助手工具轨迹展示
```

成绩、论坛、会议先写成扩展设计，不建议第一版全部开发。
