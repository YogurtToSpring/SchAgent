# CampusFlow 前端平台化架构说明

## 1. 系统定位

CampusFlow 前端现在按“校园综合服务平台”组织，而不是单一聊天页面。平台以身份权限为入口，把课程、待办、成绩、图书馆、论坛、通知、文件和智能助手放在统一工作台中。

核心逻辑：

```text
结构化业务模块负责可视化操作
智能助手负责跨模块查询、总结、生成文件和辅助决策
```

## 2. 页面版面

登录后进入 `PlatformLayout`：

```text
左侧导航：模块切换
顶部栏：当前页面、用户身份、退出
右侧主区：当前业务页面
```

左侧导航按身份生成：

```text
学生：首页、我的信息、待办、课表、成绩、图书馆、论坛、通知、文件、助手
教师：首页、我的信息、待办、教学课表、成绩录入、论坛、通知、文件、助手
管理员：首页、我的信息、待办、班级与课程、全校课表、成绩管理、论坛审核、通知、文件、助手、管理后台
```

前端同时在 `App.vue` 中维护 `canAccessView()`，即使某个消息链接直接跳转，也会按当前身份拦截不可访问页面。

## 3. 页面职责

### 首页工作台

文件：`src/pages/DashboardPage.vue`

职责：

```text
学生/教师展示天气、下一节课、待办、未读通知
管理员展示天气、平台对象、待办、未读通知
学生/教师展示今日课程
管理员展示平台概况，不展示今日课程和下一节课
提供成绩、图书馆、论坛、助手等快捷入口
```

### 我的信息

文件：`src/pages/ProfilePage.vue`

职责：

```text
个人资料
账号设置
系统设置
```

### 待办事项

文件：`src/pages/TodoPage.vue`

职责：

```text
新增待办
按今天、本周、高优先级、已完成筛选
切换完成状态
删除待办
```

待办已对接后端 `todo.py`：

```text
POST /api/todo/add
GET /api/todo/user/{user_id}
GET /api/todo
PATCH /api/todo/{todo_id}/status
DELETE /api/todo/delete
```

助手通过 `add_todo`、`update_todo_status` 等工具修改待办后，前端会刷新待办列表。

### 课表教学

文件：`src/pages/SchedulePage.vue`

职责：

```text
学生查看本人课表
教师查看本人授课课表
管理员查看全校课表表格
支持按课程、班级、教师、地点和学期检索分页
```

数据来自后端课程接口；后端不可用时使用本地缓存。

### 班级管理

文件：`src/pages/ClassAdminPage.vue`

职责：

```text
点击进入班级管理、学生班级分配、学生账号导入、课表导入四个子页面
班级管理支持创建班级、搜索筛选、分页，表格显示班级号
学生班级分配通过搜索学生和搜索目标班级完成
学生账号导入逐项填写姓名、学号、班级、密码
课表导入逐项填写课程、教师、地点、时间、周次、学期和学分
所有写入操作都需要确认
```

该页面仅系统管理员可见。创建班级时 `master_id` 来自教师编号。学生账号导入调用 `POST /api/students/register`，并同步 `classmate` 班级成员关系。课程导入调用 `POST /api/course/add`，提交字段以后端 `course.py` 为准，包括 `course_id / day / start_time / end_time / course_name / teacher_num / room_id / week_start / week_end / semester / credit`。

### 成绩系统

文件：`src/pages/GradesPage.vue`

职责：

```text
学生查看个人成绩
教师录入成绩
管理员按学号搜索学生成绩
管理员确认后修改学生成绩
管理员成绩页不展示学生式概览和成绩分析
```

成绩系统已对接后端 `grade.py` 和学生 GPA 接口：

```text
学生：GET /api/grade/student/{stu_num} + GET /api/students/{stu_num}/gpa
教师：GET /api/grade/teacher/{teacher_num}
管理员：GET /api/grade
录入：POST /api/grade/add
重复成绩修改：PATCH /api/grade/modify
GPA刷新：POST /api/students/gpa/refresh
```

### 图书馆预约

文件：`src/pages/LibraryPage.vue`

职责：

```text
选择日期、时间、馆区
查看可用座位
确认预约
自动生成图书馆待办
```

当前使用前端数据，后续可接入图书馆预约接口。

### 校园论坛

文件：`src/pages/ForumPage.vue`

职责：

```text
频道筛选
发帖
管理员审核
```

当前使用前端数据，后续可接入论坛接口。

### 通知与消息

文件：`src/pages/NotificationsPage.vue`

职责：

```text
显示课程、成绩、图书馆、论坛、系统消息
按当前身份、用户、班级过滤
单条打开并跳转模块
全部标记已读
```

### 文件中心

文件：`src/pages/FileCenterPage.vue`

职责：

```text
显示助手生成文件、课程资料、报表附件
按当前身份、用户、班级过滤
调用 GET /api/files 获取 Agent 工作区文件
支持下载
```

### 智能助手

文件：`src/pages/ChatPage.vue`

职责：

```text
多会话
流式输出
思考过程折叠
执行轨迹收起
文件下载卡片
平台上下文注入
```

## 4. 数据来源

### 后端可用接口

文件：`src/api/platform.js`

```text
学生、教师、管理员登录/注册
学生列表
教师列表
课程列表
教室列表
学生班级调整
学生账号导入注册
班级成员关系
课程创建
待办增删改查
成绩查询、录入、修改、GPA刷新
天气
```

文件：`src/api/chat.js`

```text
POST /api/chat
POST /api/chat/stream
GET /api/files/{file_name}
```

文件：`src/api/files.js`

```text
GET /api/files
```

### 前端本地业务数据

文件：`src/data/campusModules.js`

```text
待办
成绩
图书馆座位
预约记录
论坛帖子
通知消息
文件中心本地文件
系统日志
```

其中待办和成绩已有后端优先逻辑；后端不可用时仍保留本地兜底状态。图书馆、论坛、通知等模块目前仍以前端状态模拟为主。
通知和文件已经在前端按 `ownerId / audienceRoles / classId` 做身份过滤。

## 5. 状态流

核心状态集中在 `src/App.vue`：

```text
currentUser
activeView
classes / students / courses / rooms / weather
todos / grades / librarySeats / reservations
forumPosts / notifications / files / systemLogs
```

页面通过 props 读取数据，通过 emit 通知 App 修改状态。

示例：

```text
TodoPage -> add-todo -> App.addTodo()
LibraryPage -> reserve-seat -> App.reserveSeat()
ForumPage -> add-post -> App.addPost()
NotificationsPage -> open-notice -> App.openNotice()
FileCenterPage -> refresh-files -> App.refreshFiles()
```

## 6. 助手与业务模块关系

当前助手已经接入：

```text
当前用户身份
班级
学生
课程
天气
文件下载
待办工具执行后的前端刷新
```

后续建议接入：

```text
成绩分析工具
图书馆预约工具
论坛内容审核工具
通知发布工具
```

推荐调用链：

```text
用户自然语言
-> Agent 判断任务
-> 调用业务工具
-> 后端修改业务数据
-> 前端刷新模块状态
```

## 7. 后续后端替换顺序

优先级建议：

```text
1. 图书馆预约接口
2. 论坛接口
3. 通知接口
4. 文件中心归属记录
5. 系统日志接口
```

这样每次接入后端都能保留现有前端页面和交互结构。
