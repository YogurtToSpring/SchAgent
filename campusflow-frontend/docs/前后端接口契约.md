# CampusFlow 前后端接口契约

这份文档用于前端和后端统一接口格式。后端只要按这里的 JSON 返回，前端就能接入。

## 1. 当前前端接入方式

前端接口文件：

```text
src/api/chat.js
```

如果没有配置后端地址，前端使用 Mock：

```text
VITE_API_BASE_URL 未设置 -> 使用 Mock
```

如果配置了后端地址：

```text
VITE_API_BASE_URL=http://127.0.0.1:8000
```

前端会请求：

```text
POST /api/chat
```

## 2. 智能助手接口

### 请求

```http
POST /api/chat
Content-Type: application/json
```

请求体：

```json
{
  "session_id": "mock-123456",
  "message": "检查软件工程1班周三有没有课表冲突",
  "user_context": {
    "user_id": "u-teacher-001",
    "name": "林老师",
    "role": "teacher",
    "class_id": null,
    "class_ids": ["class-se-1", "class-ai-1"]
  },
  "platform_context": {
    "classes": [],
    "students": [],
    "courses": [],
    "weather": {}
  }
}
```

字段说明：

| 字段 | 类型 | 是否必需 | 说明 |
|---|---|---|---|
| `session_id` | string/null | 否 | 会话 ID，第一次可以为空 |
| `message` | string | 是 | 用户自然语言输入 |
| `user_context` | object | 是 | 当前登录用户上下文 |
| `platform_context` | object | 当前 Mock 阶段需要 | 平台数据摘要，真实后端可不需要前端传全部数据 |

真实后端上线后，更推荐：

```text
前端只传 session_id、message、user_context
后端根据 user_id 和 role 自己查数据库
```

不要长期依赖前端传完整 `platform_context`。

## 3. status 枚举

| status | 含义 | 前端表现 |
|---|---|---|
| `success` | 任务完成 | 普通回答 |
| `need_clarification` | 缺少必要信息 | 黄色提示卡 |
| `tool_error` | 工具调用失败 | 工具卡片显示失败 |
| `failed` | 后端整体失败 | 错误提示 |

## 4. tool_calls 格式

每个工具调用统一返回：

```json
{
  "tool": "course_query",
  "label": "课程查询",
  "status": "success",
  "input": {},
  "output": {}
}
```

要求：

```text
tool
程序内部工具名，英文下划线。

label
中文显示名。

status
success / failed / running / fallback。

input
工具入参。

output
工具结果或错误原因。
```

## 5. artifacts 格式

当前前端支持表格：

```json
{
  "type": "table",
  "title": "明日课程安排",
  "columns": ["课程", "时间", "地点"],
  "rows": [
    ["高等数学", "08:00-09:40", "三教302"]
  ]
}
```

后续可扩展：

```text
todo
待办清单

chart
简单图表

course_card
课程卡片

notice
通知提醒
```

## 6. 后续平台接口建议

第一版前端暂时用 Mock 数据，但后端可以按以下接口拆分：

```text
POST /api/auth/login
登录

GET /api/me
获取当前用户

GET /api/classes
获取班级列表

POST /api/classes
创建班级

GET /api/students
获取学生列表

PATCH /api/students/{id}/class
调整学生班级

GET /api/courses
获取课表

POST /api/courses/import
导入课表

POST /api/courses
新增课程

GET /api/weather/today
获取天气

POST /api/chat
智能助手
```

前端后续只需要把 `src/data/platformData.js` 的 Mock 数据替换成这些接口结果。
