# CampusFlow 前后端接口契约

## 1. 基础地址

前端通过环境变量配置后端地址：

```env
VITE_API_BASE_URL=http://127.0.0.1:8080
```

默认值位于：

```text
src/api/platform.js
src/api/chat.js
src/api/files.js
```

## 2. 登录与注册

当前前端调用 `src/api/platform.js`。

### 学生登录

```text
POST /api/students/login
```

### 教师登录

```text
POST /api/teacher/login
```

### 管理员登录

```text
POST /api/admin/login
```

### 注册

根据身份调用学生、教师或管理员注册接口。注册成功后前端会再次登录并进入平台。

## 3. 平台基础数据

前端启动或登录后会调用：

```text
GET /api/students
GET /api/teacher
GET /api/course
GET /api/room
GET /api/class-stu
GET /api/classi
GET /api/classmate
```

前端统一转换为：

```ts
classes: ClassItem[]
students: StudentItem[]
courses: CourseItem[]
rooms: RoomItem[]
teachers: TeacherItem[]
```

## 4. 课程与班级操作

### 调整学生班级

```text
PATCH /api/students/{student_id}/Cls?newcls={class_id}
POST /api/classmate/add
```

### 创建班级

```text
POST /api/classi/add
```

请求字段：

```json
{
  "class_id": "软件工程1班",
  "name": "软件工程1班",
  "master_id": "T001",
  "capacity": 45
}
```

### 导入注册学生账号

```text
POST /api/students/register
POST /api/classmate/add
```

学生注册字段：

```json
{
  "Name": "张三",
  "StuNum": "2024001",
  "Cls": "软件工程1班",
  "password": "123456"
}
```

### 创建课程

```text
POST /api/course/add
```

### 给课程关联学生

```text
POST /api/class-stu/enroll
```

课程字段：

```json
{
  "course_id": "123456",
  "day": 1,
  "start_time": "08:00",
  "end_time": "09:40",
  "course_name": "数据库原理",
  "teacher_num": "T001",
  "room_id": "3-3-301",
  "week_start": 1,
  "week_end": 16,
  "semester": "2025-2026-2",
  "credit": 2
}
```

这些接口目前由班级管理页面调用。

## 5. 天气

天气由前端直接调用 Open-Meteo，默认城市为武汉。

前端输出结构：

```json
{
  "city": "武汉",
  "weather": "小雨",
  "temperature": "23℃",
  "wind": "2级",
  "updatedAt": "今日 08:00"
}
```

## 6. 智能助手

### 普通对话

```text
POST /api/chat
```

请求结构：

```json
{
  "session_id": "可为空",
  "message": "用户问题",
  "user_context": {
    "user_id": "u-student-001",
    "name": "赵同学",
    "role": "student",
    "student_no": "2024001",
    "teacher_num": null,
    "class_id": "class-se-1",
    "class_ids": []
  },
  "platform_context": {
    "classes": [],
    "students": [],
    "courses": [],
    "weather": {}
  }
}
```

### 流式对话

```text
POST /api/chat/stream
```

前端支持事件：

```text
status
token
tool_call
tool_result
file_ready
error
done
```

`file_ready` 结构：

```json
{
  "name": "论持久战.md",
  "path": "论持久战.md",
  "size": 2910,
  "size_formatted": "2.9 KB",
  "modified_at": "2026-07-08T14:25:00",
  "download_url": "/api/files/论持久战.md"
}
```

前端处理逻辑：

```text
file_ready -> 文件 artifact -> 下载卡片
若没有 file_ready，但回答文本出现 .md/.pdf/.docx 等文件名，也会生成兜底下载卡片
```

## 7. 文件中心

### 文件列表

```text
GET /api/files
```

返回结构：

```json
{
  "files": [
    {
      "name": "论持久战.md",
      "size": 2910,
      "url": "/files/论持久战.md"
    }
  ]
}
```

### 文件下载

```text
GET /api/files/{file_name}
```

前端下载按钮默认访问：

```text
{VITE_API_BASE_URL}/api/files/{encodeURIComponent(file_name)}
```

后端负责代理 Agent 的：

```text
GET /files/{file_name}
```

中文文件名需要使用 UTF-8 `Content-Disposition`。

## 8. 待办与成绩

待办事项已对接后端 `todo.py`：

```text
POST /api/todo/add
GET /api/todo/user/{user_id}
GET /api/todo
PATCH /api/todo/{todo_id}/status
PATCH /api/todo/{todo_id}/info
DELETE /api/todo/delete
GET /api/todo/stats/{user_id}
```

成绩系统已对接后端 `grade.py` 和 `student.py` GPA 接口：

```text
GET /api/grade/student/{stu_num}
GET /api/grade/teacher/{teacher_num}
GET /api/grade
POST /api/grade/add
PATCH /api/grade/modify
DELETE /api/grade/delete
GET /api/students/{stu_num}/gpa
POST /api/students/gpa/refresh
```

图书馆、论坛、通知、系统日志目前仍主要使用 `src/data/campusModules.js` 作为前端演示数据。

后续建议继续接入：

```text

GET /api/library/seats
POST /api/library/reservations
GET /api/library/reservations

GET /api/forum/posts
POST /api/forum/posts
PATCH /api/forum/posts/{id}/review

GET /api/notifications
PATCH /api/notifications/{id}/read
PATCH /api/notifications/read-all

GET /api/files
GET /api/files/{file_name}
```

## 9. 助手后续工具建议

为了实现“助手直接操作平台”，后端 Agent 当前待办工具应和前端识别名保持一致：

```text
add_todo
delete_todo
query_todos_by_date
query_user_todos
update_todo
update_todo_status
batch_update_status
get_todo_stats
```

后续可继续增加：

```text
analyze_grades
reserve_library_seat
create_forum_post
review_forum_post
publish_notification
list_user_files
```

前端不直接调用 Agent 工具，仍通过 Backend 统一暴露接口。
